# 日电量模式与真实电站基准（v0.4）

## 1. 为什么要有"日电量模式"

pvdiag 的主力口径是 5 分钟组串电流/电压曲线：晴好天中午窗口同机互比 + 全天曲线签名（凹陷/停机/钉死/电压异位/跟踪增益）。
但接真实电站时，第一手拿到的往往不是曲线，而是**巡检报告或平台导出的"每串每日发电量（kWh）"宽表**：

```
逆变器 | 组串 | 状态   | 10-07 | 10-08 | ... | 合计kWh | 日均kWh
NB01   | pv1  | 接入   | 55.9  | 54.8  | ... | 823.0   | 35.8
NB01   | pv2  | 零电流 |       |       |     |         |
...
```

外加一张"逐日发电概况"（日期 / 中午功率 kW / 占晴峰 % / 天气 / 日发电量）。
日电量模式让智能体**用这种数据就能跑起来**，产出同样进入 `suspects` 表，复核 / 工单 / 派单门控 / 标注闭环照常接。

```bash
pvdiag daily import   --station XWZ3 --file 10月巡检.xlsx --platform huawei   # 档案 + daily_features.day_energy_kwh + station_daily 天气
pvdiag daily diagnose --station XWZ3 [--group auto|inverter|channel] [--dry-run] [--out stats.csv]
pvdiag bench --dataset real --real-dir <目录>                                 # 真实站基准（数据不入库，见 §4）
```

长表 CSV（`inverter_id, string_id|pv_index, date, energy_kwh[, status]`）同样支持；没有概况表时用全站日电量相对期内最大值 ≥35% 判晴好。

## 2. 口径

### 2.1 互比与分级
- **归一**：有档案按组件数（`n_modules`）归一，再乘 `n_parallel`（一路 MPPT 接两串并联填 2）；没有档案就按原值。
- **分组**：默认同逆变器；`auto` 下若同机组典型规模 <5 串而"同编号通道跨设备"组更大（小站、或双串/单串混接剔除后所剩无几），改用通道组——这正是 200 kW 小站报告里手工改口径的做法。
- **疑并联**：晴好天电量 ≥1.6× 群组中位的串 → "疑双串并联 / 档案缺并联数"，不作异常、也不进中位数（否则单串恒显 −50%）。
- **噪声门控**：群组 ≥6 串时算当日稳健标准差（1.4826×MAD），一次"低发"须同时 ≤ `fault_floor` 且 ≤ −`noise_k`×噪声；小组不门控。
- **分级**（证据弱于曲线，上限 B；晴好天 <5 天上限 `cold_start_cap_grade`，所有嫌疑 `low_confidence=1`）：

| 条件 | 分级 / 原因 |
|---|---|
| 档案登记了组件、全期 0 电量、同机其它串正常 | **A 断线/未接** |
| 均值 ≤ −20% 且 ≥80% 晴好天低发，均值在 −40%~−62% | **B 旁路二极管**（≈半串不发电） |
| 均值 ≤ −20%、与天气无关的恒定比例（离散 ≤2%，阴天偏差与晴天差 ≤4 点） | **C 档案差异/串长**（电压型偏差：串长/组件数不同或若干组件被旁路，电流互比看不见） |
| 均值 ≤ −20%，其余 | **B 遮挡**（遮挡/组件故障，待复核） |
| 连续 ≥`fault_persist_days` 晴好天显著低发，阴天偏差基本消失（≤3%）且离散 ≤3% | **C 朝向差异**（散射光无方向性） |
| 同上但恒定比例、与天气无关 | **C 档案差异/串长** |
| 同上，随天气变化 | **B 未知**（遮挡/积灰/组件故障） |
| 均值 ≤ 2×`fault_floor` 且 ≥80% 晴好天 ≤`fault_floor`（群组噪声大被门控掉时兜底） | C（恒定）/ B |
| 均值 ≤ `normal_floor` 且 ≤ −2×群组噪声，≥`observe_persist_days` 天 | **D 轻度** |

少发电量 = Σ晴好天 (群组中位 − 本串)×归一系数，进 `lost_kwh`。

### 2.2 通道三态（来自真实站的教训）
| 状态 | 判据 | 处理 |
|---|---|---|
| connected | 期内有电量 | 参与互比 |
| **empty_input 空输入** | 全期 0 电量、**同 MPPT 另一路在发电**、档案未登记组件数 | 不报故障。华为 SUN2000-100/110KTL、阳光 SG110CX 每 MPPT 两路输入，只接一路时空的那路读到共压电压（500~700 V）、电流恒 0——按"电压正常电流为 0"判断线会把几十上百路空输入全报成故障 |
| zero_current 零电流待核实 | 全期 0 电量、同 MPPT 两路都为 0、无档案 | 列在三态表，不单独立案；大概率整个 MPPT 未用 |
| zero_current_wired | 全期 0 电量但档案登记了组件 | **A 断线** |
| absent | 状态列 "—"，或该路编号在 ≥3 台逆变器上出现且全站无一台发过电 | 平台多报的虚拟通道 / 整站未启用输入 |
| unconnected 未接 | 状态列 "未接"（电压浮空 <400 V） | 不是故障 |

同一规则也加进了 5 分钟主链路：`DetectAgent` 对 0 电流串先查 `strings.mppt` 兄弟路，档案无组件数且兄弟路正常 → 不判断线（E 级观察，注明"空输入"）；档案有组件数 → 照报 A。

## 3. 与 5 分钟口径的差别（看结果时要记住）
- 日电量含清晨/傍晚，**朝向差异在电量上比在中午电流上大一倍以上**：中午电流 −7% 的东向串，日电量可能 −15%。所以日电量模式里 B/C 数量会比曲线口径多，C 类（朝向/档案）尤其多，它们是"去核档案"而不是"去修"。
- **电压型偏差**：串长不同（或若干组件被旁路）时电流一样、电压低 → 中午电流互比看不见，日电量（∝ V×I）看得见。真实站里就有一路 −22.7%、与天气无关、离散 1.4% 的串，电流口径的报告没有列它。
- 遮挡 / 积灰 / 组件衰减分不开（都随天气变化、都偏低），统一 B 待复核；有曲线后由签名区分。

## 4. 真实电站基准（`pvdiag bench --dataset real`）

真实站文件含客户信息，**不进仓库**：放在本地目录，`PVDIAG_REAL_DIR/manifest.json` 列出各站文件、平台、参考判定（巡检报告的 A/B/C 清单与三态计数）：

```json
{"stations": [{"station_id": "XWZ3", "file": "xxx.xlsx", "platform": "huawei", "inputs_per_mppt": 2,
               "expected": {"severe": ["NB01-pv16", "NB17-pv16"], "mild": ["..."], "healthy_examples": ["NB01-pv1", "..."]},
               "reference_states": {"connected": 216, "zero_current": 136, "unconnected": 12}}]}
```

### 4.1 三座屋顶电站（2026-10）
| 站 | 平台 / 规模 | 数据 | 报告结论 | pvdiag 日电量模式 |
|---|---|---|---|---|
| XWZ3 | 华为 FusionSolar，20 台 100/110 kW，720 路 | 23 天逐串日电量，晴好 19 天 | A 类 2 串（−23%，正午遮挡签名）；B/C ~30 串；"零电流 136 路，潜在损失可观" | **参考 A 类 2/2 召回**（B 遮挡，−27%/−23%）；参考健康串 0 误报；B 11 / C 12 / D 11；**136 路零电流全部判为空输入**（同 MPPT 兄弟路正常、无档案），12 路未接一致；另发现 1 路 −22.7% 恒定、与天气无关 → C 档案差异/串长（电流口径看不见） |
| LH | 阳光云，5 台，20 通道（MPPT1 多双串并联） | 7 天，晴好仅 2 天 | 同机互比失真，改同通道跨设备互比；"互比样本不足"，无确认故障；标注 1 路双串高流、1 路低流 | 自动切到 **通道组**；INV06-MPPT2 判为疑双串并联（与报告一致）；INV07-MPPT2 −22.6%（报告 −39% 低流）→ 因晴好天 <5 **上限 D**，与报告"样本不足"一致；0 误报 |
| JK | 阳光云，18 台 SG110CX，162 通道 | 周报只有汇总与 A/B 清单，无逐串日电量 | A 类 7 串（−48%~−61%，疑半串不发电）、B 类 7 串、空通道 53 | 只能作标签参考；口径里 −40%~−62% → B 旁路二极管（半串）正是为这类案例准备的 |

汇总：**参考严重低发召回 2/2，参考健康串 A/B 误报 0/17**。
关于 136 路"零电流"的判断（空输入而非断线）是基于华为逆变器两路共一个 MPPT 的物理事实推断，**需现场按排布图确认一次**；确认后把接线的路补进档案 `n_modules`，没接线的保持空，之后系统就按档案走。

### 4.2 从真实站学到并改进代码的点
1. 空输入规则（三态 + 主链路）——否则一座 720 路的站会报 136 条 A 级断线。
2. `n_parallel` 并联串数进档案并归一（基线 / 检测 / 日电量三处）——否则双串占多数的逆变器里单串恒显 −50%。
3. 小站自动切同通道跨设备互比。
4. "与天气无关的恒定比例"→ 档案差异/串长；"阴天消失"→ 朝向：用阴天数据区分，不再只凭幅度。
5. 平台多报的虚拟通道（全站某编号无一台发电）不当零电流。
