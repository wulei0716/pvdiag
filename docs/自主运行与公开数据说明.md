# pvdiag v0.2 · 自主运行与公开数据说明

v0.1 把 10 个阶段跑通了，但有四件事还要人盯：阈值只给建议、模型按日历重训、派单门控只显示不切换、数据缺了只告警。
v0.2 让系统自己把这四件事做掉——**每一步都有考试、有边界、有留痕、能撤回**，并且用两份公开的真实光伏数据给整条链路做了"考试"。

---

## 1. 四个自主闭环

### 1.1 阈值自调参（TuningAgent，阶段 4·块二）

| 问题 | 做法 |
|---|---|
| 调什么 | `thresholds.fault_floor`（持续低发阈值，-8%~-4%）、`fault_persist_days`（2~4 天）、`noise_k`（2.0~4.0） |
| 考题从哪来 | 近 60 天已复核的"纯偏差型"案例（B/D 级、无凹陷/停机/钉死/电压签名）：确认/修改 = 正例，驳回 = 负例 |
| 怎么考 | **影子回放**：用候选参数在每个案例所在组串的历史晴好天偏差序列上重判"会不会报 B" → 精确率/召回/F1 |
| 什么时候生效 | 候选只改一个参数、F1 提升 ≥5 个百分点、对已确认案例的召回 ≥ 当前 × 80%、距上次调整 ≥7 天、样本 ≥20 条 |
| 生效到哪 | 写运行时覆盖层 `param_overrides`（`config.yaml` 不动，人工口径与机器口径分层）；全部变更进 `param_changes` 留痕 |
| 怎么撤回 | 生效 ≥3 天且新增 ≥10 条 B 级复核后，确认率比生效前跌 ≥10 个百分点 → **自动回滚**并推送；`pvdiag tune rollback|clear` 手动 |
| 放松怎么办 | 放松阈值会引入"从未报过所以没有标注"的串，无法用已有标注验证 → 现场漏报 ≥3 起时只**提议**（含预计新增报警数），人确认后 `pvdiag tune apply` |

`autotune.mode: shadow` 可改成只评估不生效。`pvdiag tune show` 能看到当前口径、覆盖层、留痕和影子回放的参数网格成绩。

### 1.2 模型生命周期（ClassifyAgent）

- **触发**：标注达到 `min_labels_for_ml` 首次训练；新增标注 ≥20 条；到周期（30 天）且有新标注 ≥5；偏差分布 PSI >0.25 且有新标注。
- **考试**：按案例首次报警日排序，留出最近 25%（≥10 条）做 time holdout（样本太少退化为交叉验证）。同一张卷子考三个人：挑战者（新模型）、现役模型、规则代理（规则原因直接当答案）。
- **上线**：挑战者准确率 ≥ 规则代理 − 2% 且 ≥ 现役 − 2%；否则注册表记 `rejected`，继续用现役/规则代理。`pvdiag train --force` 可人工强制。
- **一个已知偏置**：直接"确认"的标注 = 规则原因本身，规则代理在这些行上天然全对，所以这条上线门槛是偏向规则代理的（宁可不上线）。考试同时给出只在"修改原因/驳回"行上的成绩（`challenger_on_corrected` / `rule_proxy_on_corrected`），复核时多用"修改原因"而不是直接确认，模型才学得到规则学不到的东西。
- **线上监督**：每天用近 30 天复核结论算"模型一致率 vs 规则代理一致率"（n ≥20）；模型落后 ≥10 个百分点 → 自动 `demoted`，回退规则代理并推送。`pvdiag model list|promote|demote`。

### 1.3 派单门控自动开合（WorkOrderAgent，`dispatch.mode: gated`，默认）

- 门控条件：近 30 天复核 ≥30 条且误报率 <10%（原有口径）。
- **放开**：门控连续 ≥7 个运行日通过 → `effective=auto`，高置信 A/B 工单自动发送。
- **收回**（任一即刻）：门控不通过；当天任一智能体失败；任一电站数据时延 >2 天；窗口内现场漏报 ≥3 起。
- 每次开合写入 `platform_state['dispatch:gate'].history` 并推送。`draft` 永远草稿，`auto` 保持 v0.1 语义（当天通过即自动）。`pvdiag gate status|open|close`。

### 1.4 数据接入自愈（IngestAgent）+ 自检 + 推送

- 每次运行回看 14 天，**缺哪天补哪天**（单次 ≤7 天，控制配额），比首个数据日更早的不算缺口。
- 适配器拉取失败：指数退避重试 3 次（5/10/20 s）→ 若电站配置了 `fallback_csv_root`，**降级读本地落地文件**（对接已有拉数脚本）→ 仍失败则计数，连续 ≥3 次升级 `error` 并推送。
- 数据冻结（电流钉死 ≥90 分钟）不再被误标为限发；半天钉死也能判"数据问题"。
- `pvdiag doctor`：SQLite 完整性/WAL、磁盘、目录可写、每站数据新鲜度与失败计数、每日巡检是否在跑、今日智能体、模型文件与线上一致率、阈值自洽、覆盖层、门控。MonitorAgent 每天自动跑同一套，`fail` 项推送。
- 推送（`pvdiag/notify.py`）：企业微信 webhook，没配就写 `data/outbox/alerts/<date>.md`；同一内容 24 小时只推一次。推送内容只有人必须知道的：管道 error、自检 fail、门控开合、模型上线/未过考/降级、参数生效/回滚。
- 老数据库自动补列迁移（`storage._MIGRATIONS`），升级 v0.2 不需要迁移脚本。

控制台新增「自主运行」页（`/autonomy`）：门控状态与开合历史、当前口径与覆盖层、参数变更留痕、模型注册表与考试成绩、健康自检、接入自愈状态、已推送事件。

## 2. 公开数据：怎么拿、怎么用、考出了什么

沙箱与多数内网只放行 GitHub/PyPI，所以：

| 数据 | 来源 | 用途 |
|---|---|---|
| Kaggle《Solar Power Generation Data》 | GitHub 公开镜像（4 个 CSV，sha256 校验），`pvdiag public fetch kaggle_solar` | 两座印度电站 × 22 台逆变器、15 分钟 DC/AC 功率 + 气象站辐照/温度、2020-05-15~06-17 |
| NREL 标注片段 | 随 `pvanalytics` 包分发（`pip install -e ".[bench]"`） | `ac_power_inv_2173_stale_data`（人工标注钉死）、`ac_power_inv_7539`（人工标注限发） |

**映射**：Kaggle 只有逆变器级功率，没有组串 → 整站当一台"虚拟逆变器"，22 台真实逆变器当 22 路"组串"，pvdiag 的"同机互比"在这里就是"同站各逆变器互比"，口径不变。Plant 1 的 DC 功率已知比 AC 大 10 倍（数据瑕疵），已复原。15 分钟 → 5 分钟按日线性插值，缺测保持缺测。气象站辐照进 `station_daily.irradiance_kwh_m2`，天气判定会用它校正。

**参考标签**（独立于 pvdiag 口径，从原始数据统计）：`underperform`（干净日电量比 ≤0.95）、`mild`（≤0.975）、`intermittent_outage`（白天零输出 ≥20% 的天数 ≥5）、`normal`。详见 `pvdiag/public/kaggle_solar.py`。

**考出了什么、改了什么**（改进前 → 改进后，见 `docs/公开数据基准报告.md`）：

| 现象 | 根因 | 改进 |
|---|---|---|
| Plant 1 健康机器 4 台被判 B | 大电站"晴好天"各机偏差稳健标准差 2%~7%，-5% 只是云影噪声；头两天冷启动就下 B | **群组噪声门控**（偏差还要 ≤ -k×群组 MAD 才算显著，噪声 >4% 的日子不计也不打断持续度）；**冷启动只给到 D** |
| Plant 2 的 18 台间歇掉线全判"遮挡" | 白天整段 0 输出被当成"凹陷" | 新增原因 **间歇停机/掉线** 与签名（≤ 群组同时段 10% 视为整段为 0；停机日不计入互比持续度；近 7 天仍有停机不自愈关案） |
| 一台机器先"停机"后"旁路二极管" | 案例原因被最后一天覆盖 | 案例原因**多数票**（未知不覆盖具体原因；分级升级以今天为准）；新增 `suspect_daily` 每日快照 |
| NREL 钉死日被标成"限发" | 功率冻结看起来像平顶 | 组串电流钉死 ≥90 分钟的机器不标限发；半天钉死进"数据问题" |
| 天气只看功率，与辐照不符 | 功率 ≥35% 峰值且 CV ≤0.15 太宽 | 有辐照时：<50% 近期晴天参考 → 阴雨；<75% → 不算晴好天 |

**用公开数据训练**：`pvdiag bench --dataset train` 把两座 Kaggle 电站 + 一座合成电站灌进同一个库，用参考标签/注入真值自动"复核"（弱标注），训练分类模型并按时间留出集考试。结果：53 条标注、10 类，随机森林在留出集 69% 对 规则代理 54%，达标上线，随后的判定使用 ML 模型。这验证的是**链路**（标注 → 训练 → 考试 → 上线 → 判定）在真实数据上能跑通，以及"考不过就不上线"的闸门真的会拦（第一版因留出集切分用错日期字段，挑战者 8%，被闸门拦下——这正是闸门的价值）。弱标注不等于现场标注，上生产仍以复核结论为准。

## 3. 日常操作速查

```bash
pvdiag doctor                      # 健康自检（退出码 1 = 有 fail）
pvdiag tune show                   # 当前口径 / 覆盖层 / 变更留痕 / 影子回放成绩
pvdiag tune apply thresholds.fault_floor -0.04 --note "现场漏报多"   # 人工生效（写覆盖层）
pvdiag tune rollback | clear       # 回滚最近一次 / 清空覆盖层回到 config.yaml
pvdiag gate status | open | close  # 派单门控
pvdiag model list | promote <ver> | demote
pvdiag public fetch kaggle_solar   # 下载公开数据（GitHub 镜像 + sha256）
pvdiag public load --plant 1       # 把 Kaggle Plant 1 当电站入库，然后 pvdiag backfill 回放
pvdiag bench --dataset all --out ./bench   # 全部基准 + 弱标注训练，生成 bench_report.md/json
```

## 4. 安全边界（刻意保留的"人在环"）

- 自调参只在区间内一步、只收紧不自动放松、能回滚；`shadow` 模式一键只看不动。
- 模型不达标不上线，上线后一致率落后自动降级；人工 `promote/demote` 永远可用。
- 自动派单只在门控连续达标后放开，管道任何异常立即收回；`mode: draft` 彻底关掉。
- 所有自动动作都进 `param_changes / model_registry / dispatch:gate.history / alerts`，控制台「自主运行」页一屏可查，关键事件推送到企业微信。
