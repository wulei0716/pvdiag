## 读法

- **召回 38/40、31/31，健康串零误报**：合成世界噪声只有 1%，比真实电站干净，所以阈值过紧也不产生误报，自调参没有可修的东西——它正确地什么都没做。
  要看自调参真正"动"起来，看公开数据基准（Kaggle 两站噪声 2%~7%）和 `tests/test_autonomy.py` 里的构造考题。
- **模型闸门**：场景 B 标注到 30 条就训练，但留出集准确率低于规则代理 → 拒绝上线。这是预期行为：规则代理在"直接确认"的标注上天然全对，模型要赢得先有足够多"修改原因/驳回"的样本。
- **门控**：误报率要连续 7 个运行日 <10% 且复核 ≥30 条才放开——场景 A 第 125 天、场景 B 第 176 天。这个节奏对一个新电站是合理的（先让人复核一两个月）。
- **发现时延中位 0~1 天**：绝大多数注入故障在第 1~2 个晴好天被报出。2 个未召回的是慢积灰/小幅阶跃（-7%）在到期前没凑够持续度——由区域智能体的积灰签名和 D 级观察带兜着。
- **流水线 0 天中断**：压测第一轮抓到一个 ZeroDivisionError（朝向差异修复成本为 0 做了分母），已修。
- **现场回填产生标注**（v0.3 新增）：工单回填的实际原因自动写入复核表（原因一致 confirm / 不一致 modify / "正常·误报" reject），这是最可靠的标注来源，也是场景里复核样本的主要来源。
